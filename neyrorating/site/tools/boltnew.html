Bolt.new

Bolt.new создаёт сайты и приложения из текстового задания в браузере. Позволяет уточнять проект, смотреть код и подключать инфраструктуру для работы с данными.

Что создаёт браузерный конструктор

Bolt.new использует ИИ для подготовки сайтов и приложений по описанию. В документации указана работа с веб-проектами на JavaScript и мобильными приложениями через интеграцию Expo. В браузере можно обсуждать задачу, просматривать проект и проверять поведение. Для инфраструктуры предусмотрены средства Bolt Cloud и подключение сторонних сервисов.

Для первого опыта подходит приложение с понятной последовательностью действий. Например, небольшой список оборудования, где сотрудник добавляет предмет, отмечает его доступность и ищет нужную запись. Такой проект позволяет проверить форму, состояние списка и сохранение информации. До работы определите, будет ли это личный инструмент или сервис для нескольких пользователей.

Требования до генерации экранов

Запишите, что считается одной записью оборудования. Название, внутренний номер и статус должны иметь разные назначения. Если внутренний номер уникален, это правило нужно обозначить заранее. Для общего каталога также решите, кто может редактировать записи и что произойдёт при одновременных изменениях.

Выберите, какие данные нужны в прототипе. Используйте вымышленные предметы и сотрудников, пока не подтверждены правила доступа. Перечислите состояния интерфейса: список загружается, записей нет, сохранение не удалось. Иначе генерация может сосредоточиться на наполненном экране и оставить рабочие ошибки без объяснения.

Собери веб-приложение учёта оборудования. В списке нужны название, внутренний номер и доступность. Добавление выполняется через форму, поиск работает по названию. Покажи пустой список и ошибку сохранения. Начни с вымышленных данных. Сначала предложи устройство проекта и уточни, где будет храниться информация.

После плана проверьте, соответствует ли выбранная технология окружению команды. Если уже есть сервер или база, укажите их до начала реализации. Подключение нового хранилища без необходимости усложняет дальнейшую поддержку. Для самостоятельного прототипа можно сначала проверить взаимодействие экранов, затем добавить постоянное хранение.

Предпросмотр и обычные действия

Откройте предпросмотр и добавьте предмет. Затем измените статус и найдите его по части названия. Проверьте кириллицу и длинное название. Поиск должен вести себя понятно при пустом запросе и отсутствии совпадений. На телефоне действия с записью должны оставаться доступными без горизонтального прокручивания.

Обновите страницу. Если список исчез, выясните, использовалась ли только память браузерного сеанса. Для рабочего приложения нужно согласованное постоянное хранение. При наличии базы убедитесь, что запись действительно появилась в ней и повторный вход возвращает ожидаемый результат. Внешне работающая форма может менять только локальное состояние.

После каждой просьбы о правке повторяйте связанный сценарий. Изменение поиска способно затронуть выбранную запись или счётчик результатов. В задании называйте проблему: после очистки поиска список остаётся пустым. Конкретное наблюдение помогает найти причину быстрее, чем общее требование исправить интерфейс.

Код и зависимости

Bolt предоставляет просмотр кода. Изучите изменённые файлы, особенно обработку данных и подключение внешних ресурсов. Если агент добавляет пакет, попросите объяснить его назначение. Зависимость, нужная только для декоративного эффекта, может оказаться лишней для простого рабочего списка.

Проверьте команды запуска и сборки. Сообщение агента об исправлении следует сравнивать с журналом и состоянием проекта. Если сборка завершилась ошибкой, опубликованный интерфейс нельзя считать подтверждённым результатом. Для команды полезно сохранить воспроизведение ошибки и точное место, где проверка остановилась.

Версионный контроль помогает отделять эксперименты от рабочих правок. Перед крупным изменением сохраните понятное состояние. При подключении GitHub проверьте репозиторий и порядок синхронизации. Не запускайте одновременно несогласованные изменения из разных сред, пока не определён способ объединения правок.

Данные, секреты и интеграции

Инфраструктура Bolt Cloud включает работу с базами и размещением; в документации также описаны внешние подключения. Выберите один понятный маршрут данных для своего проекта. Для пользователя с правом просмотра отдельно проверьте невозможность изменить записи. Скрытая кнопка редактирования не ограничивает доступ на уровне серверного запроса.

Ключи подключений храните согласно предусмотренному механизму секретов. Перед публикацией посмотрите, какие значения попадают в браузерные файлы. В проекте с несколькими сотрудниками необходимо определить вход и полномочия. Для тестирования используйте аккаунты с разными разрешениями и записи, которые разрешено менять.

Если планируется мобильная версия, изучите сценарий Expo отдельно. Веб-предпросмотр не подтверждает поведение приложения на устройстве. Разрешения камеры, файлов и уведомлений требуют проверки в целевом окружении. Сначала согласуйте, какие возможности действительно нужны, затем добавляйте их к рабочему сценарию.

После публикации

Откройте публичный адрес в новом сеансе и повторите добавление, поиск и изменение записи. Проверьте, какой проект и версия опубликованы. Уберите учебное наполнение и случайные секреты из доступных файлов. Сохраните инструкции запуска и описание хранилища, если приложение будет передано разработчику для дальнейшей поддержки. Проверку лучше повторить с пользователем, которому доступно только чтение, чтобы увидеть реальные ограничения.

Для другого диалогового конструктора сравните Lovable. Если основная задача состоит в разработке интерфейса, изучите v0. Другие решения находятся в категории конструкторов сайтов и интерфейсов; сравнивайте на одном пользовательском сценарии.

Практика в Молекуле

Описать логику приложения перед сборкой

Составьте спецификацию приложения учёта заявок перед работой в конструкторе. Молекула поможет подготовить описание экранов и пример логики; сборка в выбранной no-code платформе, настройка доступа и публикация приложения остаются отдельными действиями.

  1. Назовите роли пользователей и обязательные поля заявки.
  2. Попросите схему экранов и переходов между статусами.
  3. Сверьте спецификацию с возможностями своего конструктора.
Пример запроса

Подготовь спецификацию приложения заявок для небольшой мастерской. Есть клиент, менеджер и исполнитель. Опиши поля, статусы, доступ каждой роли и действия на экранах без привязки к платформе.
